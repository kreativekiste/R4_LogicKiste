📘 ARDUINO R4_LOGICKISTE - BENUTZERHANDBUCH & DOKUMENTATION

1. EINLEITUNG: WAS IST DIE R4_LOGICKISTE?

Die R4_LogicKiste ist eine visuelle Programmierumgebung, die speziell für den Arduino UNO R4 WiFi entwickelt wurde. Anstatt C++ Code von Hand tippen zu müssen, steckst du das Programm aus Logik-Blöcken zusammen.

Wie funktioniert das?
Das Herzstück der LogicKiste ist ein intelligenter Generator, der direkt im Browser läuft. Während Blöcke auf die Arbeitsfläche gezogen werden, übersetzt das System die Logik im Hintergrund in C++ Code. Du lernst das EVA-Prinzip (Eingabe, Verarbeitung, Ausgabe) intuitiv kennen und kannst dir den Code ansehen, um den Übergang zur Textprogrammierung zu meistern.

2. NUTZUNG: ONLINE VS. OFFLINE

Die gesamte Code-Generierung passiert lokal im Browser. Du hast zwei Möglichkeiten:

Variante A: Online nutzen (Im Browser)

Die LogicKiste wird über die Webseite aufgerufen. Es ist keine Installation nötig. Den generierten Code kannst du über "Code kopieren" in die Arduino IDE einfügen und hochladen.

Variante B: Offline nutzen (Lokal auf dem PC)

Du kannst die Projektdateien herunterladen, den Ordner entpacken und die Datei index.html im Browser öffnen. So ist die LogicKiste komplett lokal und ohne Internetverbindung nutzbar.

3. BOARD

Das Fundament für jedes Programm.

➔ Block: Programm Start (Main)

  • Ordner/Datei: js/generator_core.js
  • Menü: Board

Beschreibung:
Das Herzstück des Codes. Unterteilt das Programm in GLOBAL (Bibliotheken), SETUP (einmalige Ausführung beim Start) und LOOP (Endlosschleife).

  • Praxis-Beispiel: Hier werden alle weiteren Blöcke des Programms eingeklinkt.
  • Wichtige Hinweise: Dieser Block kann nicht gelöscht werden. Ohne ihn wird kein Code generiert.
  • UNO R3 Kompatibel: ✅ JA

➔ Block: Hardware Interrupt (PC Interrupt)

  • Ordner/Datei: blocks/board/interrupts.js
  • Menü: Board

Beschreibung:
Unterbricht das Hauptprogramm bei einem Flankenwechsel am Pin sofort, führt den angedockten Code aus und kehrt zurück.

  • Praxis-Beispiel: Einen Not-Aus-Schalter abfragen oder einen extrem schnellen Drehzahlmesser auslesen.
  • Wichtige Hinweise: Der Code im Interrupt muss extrem kurz sein (kein delay!). Verwendete Variablen müssen zwingend als Interrupt-Variable (volatile) deklariert sein. Empfohlene Pins am R4: 2, 3, 8 oder 13.
  • UNO R3 Kompatibel: ✅ JA

4. EINGÄNGE

Die Sensoren und Taster des Arduinos.

➔ Block: Aktiviere internen Pullup

  • Ordner/Datei: blocks/input/setup_pullup.js
  • Menü: Eingänge ➔ Standard Pins

Beschreibung:
Schaltet den internen Widerstand eines digitalen Pins ein, um den Pin dauerhaft auf HIGH zu ziehen.

  • Praxis-Beispiel: Nackte Taster direkt zwischen Pin und GND anschließen, ohne externe Widerstände zu verbauen.
  • Wichtige Hinweise: Muss in den SETUP-Bereich. Ein gedrückter Taster liefert dann LOW (FALSCH), ein losgelassener HIGH (WAHR).
  • UNO R3 Kompatibel: ✅ JA

➔ Block: Lese digitalen PIN

  • Ordner/Datei: blocks/input/read_digital.js
  • Menü: Eingänge ➔ Standard Pins

Beschreibung:
Liest den Zustand eines Pins aus (WAHR/HIGH oder FALSCH/LOW).

  • Praxis-Beispiel: Abfragen, ob ein Schalter umgelegt oder ein Taster gedrückt ist.
  • Wichtige Hinweise: Pin muss korrekt beschaltet sein (Pullup/Pulldown), um schwebende Zustände zu vermeiden.
  • UNO R3 Kompatibel: ✅ JA

➔ Block: Lese analogen PIN

  • Ordner/Datei: blocks/input/read_analog.js
  • Menü: Eingänge ➔ Standard Pins

Beschreibung:
Misst Spannungen stufenlos und gibt sie als Zahlenwert zurück.

  • Praxis-Beispiel: Stellung eines Drehreglers (Potentiometer) bestimmen.
  • Wichtige Hinweise: Funktioniert nur an analogen Pins (A0 bis A5).
  • UNO R3 Kompatibel: ✅ JA

➔ Block: Analogwert Glätten

  • Ordner/Datei: blocks/input/analog_smooth.js
  • Menü: Eingänge ➔ Standard Pins

Beschreibung:
Beruhigt schwankende analoge Sensorwerte durch die Bildung eines gleitenden Mittelwerts.

  • Praxis-Beispiel: Stabilisierung von stark schwankenden Lichtsensorwerten.
  • Wichtige Hinweise: Benötigt etwas Speicher für das Array im Hintergrund.
  • UNO R3 Kompatibel: ✅ JA

➔ Block: Tasterdruck Zähler

  • Ordner/Datei: blocks/input/input_counter.js
  • Menü: Eingänge ➔ Taster & Zähler

Beschreibung:
Zählt Tasterdrücke und integriert automatisch eine Entprell-Funktion (Debounce), um mechanische Wackler herauszufiltern.

  • Praxis-Beispiel: Menüseiten auf einem Display durchschalten.
  • Wichtige Hinweise: Ersetzt komplizierte millis()-Konstrukte zur Tasterentprellung.
  • UNO R3 Kompatibel: ✅ JA

➔ Block: Drehgeber (Rotary Encoder)

  • Ordner/Datei: blocks/input/input_encoder.js
  • Menü: Eingänge ➔ Taster & Zähler

Beschreibung:
Liest die Endlos-Drehbewegung eines Encoders aus und aktualisiert kontinuierlich einen Variablenwert.

  • Praxis-Beispiel: Helligkeit einstellen oder in Menüs scrollen.
  • Wichtige Hinweise: Benötigt zwei Pins (CLK und DT).
  • UNO R3 Kompatibel: ✅ JA

➔ Block: DHT Sensor (Temperatur/Feuchtigkeit)

  • Ordner/Datei: blocks/sensor/dht_sensor.js
  • Menü: Eingänge ➔ Sensoren

Beschreibung:
Liest Werte eines DHT11 oder DHT22 aus (Temperatur oder Luftfeuchtigkeit).

  • Praxis-Beispiel: Steuerung eines Lüfters ab 25 Grad.
  • Wichtige Hinweise: Benötigt die DHT.h Bibliothek. Maximal einmal pro Sekunde auslesen, da der Sensor extrem träge ist.
  • UNO R3 Kompatibel: ✅ JA

➔ Block: Ultraschall Sensor (HC-SR04)

  • Ordner/Datei: blocks/sensor/ultrasonic_hc_sr04.js
  • Menü: Eingänge ➔ Sensoren

Beschreibung:
Misst Distanzen zu Hindernissen per Ultraschall-Laufzeit und gibt diese in Zentimetern aus.

  • Praxis-Beispiel: Roboterauto vor einer Wand stoppen lassen.
  • Wichtige Hinweise: Benötigt Trigger- und Echo-Pin. Die integrierte Intervall-Messung verhindert das Blockieren der Loop.
  • UNO R3 Kompatibel: ✅ JA

➔ Block-System: Gyro Sensor (MPU6050)

  • Ordner/Datei: blocks/sensor/gyro_mpu6050.js
  • Menü: Eingänge ➔ Sensoren

Beschreibung:
Liest Beschleunigung, Rotation oder Temperatur über den I2C-Bus aus.

  • Praxis-Beispiel: Digitale Wasserwaage bauen.
  • Wichtige Hinweise: Setup-Block muss in den Setup-Bereich. Benötigt Adafruit MPU6050 Library.
  • UNO R3 Kompatibel: ✅ JA

➔ Block-System: RFID (RC522)

  • Ordner/Datei: blocks/advanced/rfid_rc522.js
  • Menü: Eingänge ➔ Sensoren

Beschreibung:
Erkennt NFC/RFID-Chips und gleicht deren UID ab.

  • Praxis-Beispiel: Elektronisches Türschloss.
  • Wichtige Hinweise: Nutzt den SPI-Bus (MISO, MOSI, SCK fest vorgegeben). Setup-Block muss in den Setup-Bereich.
  • UNO R3 Kompatibel: ✅ JA

5. AUSGÄNGE

Signale senden, Motoren steuern und Displays beschreiben.

➔ Block: Schreibe digitalen PIN

  • Ordner/Datei: blocks/output/write_digital.js
  • Menü: Ausgänge ➔ Standard Pins

Beschreibung:
Schaltet einen Pin auf HIGH (5V) oder LOW (0V).

  • Praxis-Beispiel: LED einschalten oder Relais schalten.
  • Wichtige Hinweise: PinMode wird automatisch generiert.
  • UNO R3 Kompatibel: ✅ JA

➔ Block: Schreibe analogen PIN (PWM)

  • Ordner/Datei: blocks/output/write_analog.js
  • Menü: Ausgänge ➔ Standard Pins

Beschreibung:
Gibt per Pulsweitenmodulation einen Wert zwischen 0 und 255 aus.

  • Praxis-Beispiel: LED dimmen oder Motor-Geschwindigkeit regeln.
  • Wichtige Hinweise: Funktioniert nur an PWM-fähigen Pins (markiert mit ~).
  • UNO R3 Kompatibel: ✅ JA

➔ Block: Spiele Ton (Buzzer)

  • Ordner/Datei: blocks/output/output_tone.js
  • Menü: Ausgänge ➔ Standard Pins

Beschreibung:
Gibt ein Rechtecksignal mit festgelegter Frequenz und Dauer aus.

  • Praxis-Beispiel: Akustisches Feedback bei Tastendruck.
  • Wichtige Hinweise: Blockiert das Programm nicht, läuft über Hardware-Timer.
  • UNO R3 Kompatibel: ✅ JA

➔ Block-System: Servo

  • Ordner/Datei: blocks/motor/motors.js
  • Menü: Ausgänge ➔ (Motoren)

Beschreibung:
Fährt einen Servomotor auf einen bestimmten Winkel (0-180 Grad). Enthält Blöcke für direkte Fahrt, Rampen-Fahrt sowie Attach/Detach.

  • Praxis-Beispiel: Schranke öffnen.
  • Wichtige Hinweise: Servos benötigen viel Strom. Externe Stromversorgung nutzen.
  • UNO R3 Kompatibel: ✅ JA

➔ Block-System: Stepper (Schrittmotor)

  • Ordner/Datei: blocks/motor/stepper_advanced.js
  • Menü: Ausgänge ➔ (Motoren)

Beschreibung:
Präzise Steuerung von Schrittmotoren über Einzelschritte.

  • Praxis-Beispiel: Achsensteuerung für Automatisierungsprojekte.
  • Wichtige Hinweise: Setup-Block zwingend im Setup-Bereich platzieren.
  • UNO R3 Kompatibel: ✅ JA

➔ Block-System: NeoPixel

  • Ordner/Datei: blocks/visuals/neopixel_basic.js
  • Menü: Ausgänge ➔ Licht & Matrix

Beschreibung:
Steuert intelligente WS2812 LED-Streifen. Farben werden gesetzt und mit dem "Show"-Block an die Hardware gesendet.

  • Praxis-Beispiel: Treppenbeleuchtung oder Status-Licht.
  • Wichtige Hinweise: Benötigt Adafruit_NeoPixel.h. Immer externen Strom nutzen, R4 liefert nicht genug Strom für viele LEDs.
  • UNO R3 Kompatibel: ✅ JA

➔ Block-System: R4 Onboard Matrix

  • Ordner/Datei: blocks/visuals/r4_matrix.js
  • Menü: Ausgänge ➔ Licht & Matrix

Beschreibung:
Steuert die interne 12x8 LED-Matrix des Arduino R4 WiFi. Bietet Symbole, statischen Text, blockierende Laufschriften und direkte Pixel-Ansteuerung.

  • Praxis-Beispiel: Spielstandsanzeige direkt auf dem Mainboard.
  • Wichtige Hinweise: Setup-Block muss ins Setup. Laufschrift pausiert das Programm.
  • UNO R3 Kompatibel: ❌ NEIN (Nur R4 WiFi Hardware)

➔ Block-System: MAX7219 Matrix

  • Ordner/Datei: blocks/visuals/max7219_matrix.js
  • Menü: Ausgänge ➔ Licht & Matrix

Beschreibung:
Steuert externe 8x8 Dot-Matrix-Module über SPI. Ideal für Laufschriften.

  • Praxis-Beispiel: Große Laufschrift für Fenster.
  • Wichtige Hinweise: Benötigt MD_Parola.h. Animations-Block muss zyklisch im Loop aufgerufen werden.
  • UNO R3 Kompatibel: ✅ JA

➔ Block-System: I2C LCD Display

  • Ordner/Datei: blocks/visuals/lcd_i2c.js
  • Menü: Ausgänge ➔ Displays

Beschreibung:
Steuert Text-LCDs über den I2C-Bus (SDA/SCL).

  • Praxis-Beispiel: Text-Menü für Steuerungen.
  • Wichtige Hinweise: Setup-Block erforderlich. I2C Adresse prüfen (oft 0x27 oder 0x3F).
  • UNO R3 Kompatibel: ✅ JA

➔ Block-System: TFT Displays

  • Ordner/Datei: blocks/visuals/tft_displays.js
  • Menü: Ausgänge ➔ Displays

Beschreibung:
Farb-Displays (ST7735 / ILI9486) zur grafischen Ausgabe von Formen und Text.

  • Praxis-Beispiel: Sensor-Dashboard oder Oszilloskop.
  • Wichtige Hinweise: Extrem speicherhungrig. Nutzt den SPI Bus.
  • UNO R3 Kompatibel: ⚠️ EINGESCHRÄNKT (RAM-Limit beim R3)

➔ Block-System: TM Displays (TM1637 / TM1638)

  • Ordner/Datei: blocks/visuals/visu_tm.js
  • Menü: Ausgänge ➔ Displays

Beschreibung:
7-Segment-Anzeigen. TM1637 für 4 Ziffern, TM1638 für 8 Ziffern inklusive LEDs und Tasterauswertung.

  • Praxis-Beispiel: Digitale Stoppuhr oder Tastenpult.
  • Wichtige Hinweise: Setup-Block muss ins Setup.
  • UNO R3 Kompatibel: ✅ JA
